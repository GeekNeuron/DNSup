# DNSup

ابزار بررسی وضعیت DNSهای عمومی و تست سرعت اینترنت.

## قابلیت‌ها

- بررسی زمان پاسخ (پینگ) چند سرور DNS عمومی و مقایسهٔ آن‌ها با هم.
- فیلتر بر اساس کشور (جهانی، ایران، روسیه، یا کشورهای دلخواهی که خودتان اضافه می‌کنید) + برچسب‌هایی مثل گیمینگ، امنیتی، رفع تحریم.
- افزودن، ویرایش و حذف DNS دلخواه، با اعتبارسنجی IPv4/IPv6.
- نشان‌گذاری خودکار سریع‌ترین DNS در فیلتر فعلی.
- تست سرعت دانلود/آپلود/پینگ اینترنت.
- رابط کاربری فارسی/RTL به‌صورت پیش‌فرض، با امکان تعویض به انگلیسی.
- تم روشن/تاریک، با ذخیرهٔ همهٔ تنظیمات و داده‌های کاربر بین بازدیدها.
- قابل‌نصب به‌صورت PWA (اپلیکیشن وب پیشرو).

## دیتاست DNS

۱۷ سرور از پیش تعریف‌شده شامل سرویس‌های شناخته‌شدهٔ جهانی (Google، Cloudflare، OpenDNS، Quad9، AdGuard، CleanBrowsing، Comodo، Verisign، Control D، DNS.WATCH)، یک سرویس روسی (Yandex)، و شش سرویس ایرانی (Shecan، Electro، 403 Online، Radar Game، Begzar، DNS Pro). همهٔ آدرس‌ها پیش از افزودن، از چند منبع مستقل راستی‌آزمایی شدند.

**نکتهٔ فنی دربارهٔ DNSهای ایرانی**: «403 Online» و «Radar Game» از رنج آدرس خصوصی (`10.202.x.x`) استفاده می‌کنند که فقط از داخل زیرساخت ملی ایران قابل‌دسترسی است؛ اگر از بیرون ایران تست کنید همیشه بی‌پاسخ می‌ماند و این طبیعی است، نه باگ. Begzar، DNS Pro و بقیهٔ موارد از آدرس عمومی واقعی استفاده می‌کنند و از هرجا قابل تست‌اند.

برچسب «🎮 گیمینگ» یا «🔓 رفع تحریم» روی هر تایل، بر اساس هدف اعلام‌شدهٔ همان سرویس است، نه یک اندازه‌گیری واقعی پینگ سرور بازی — چون از جاوااسکریپت مرورگر نمی‌شود پینگ واقعی یک سرور بازی خاص را از طریق یک DNS خاص سنجید. برای مقایسهٔ واقعی، همان عدد پینگ بالای هر تایل را ببینید.

می‌توانید یک کشور کاملاً جدید (با کد، نام و پرچم دلخواه) هنگام افزودن یا ویرایش هر DNS تعریف کنید؛ فیلتر بالای صفحه به‌صورت خودکار آن را نشان می‌دهد.

## روش اندازه‌گیری پینگ

مرورگرها اجازه نمی‌دهند جاوااسکریپت یک صفحهٔ وب، سرور DNS سیستم را عوض کند یا آزادانه به هر IP دلخواه کوئری DNS واقعی بفرستد و پاسخش را بخواند (محدودیت CORS). به همین دلیل، برای هر سرور در ابتدای کار بررسی می‌شود که آیا واقعاً امکان خواندن پاسخ DoH آن وجود دارد یا نه:

- اگر بله: پینگ «✓ دقیق» است — یعنی یک پاسخ واقعی DNS دریافت و تأیید شده.
- اگر نه (که برای اکثر سرویس‌ها همین‌طور است): پینگ «≈ تقریبی» گزارش می‌شود — یعنی فقط زمان برقراری اتصال HTTPS به همان IP اندازه‌گیری شده، نه یک پاسخ DNS تأییدشده.

این بررسی هر ۳۰ دقیقه یک‌بار تکرار می‌شود چون ممکن است تنظیمات یک سرویس در طول زمان تغییر کند. هر اندازه‌گیری از چند نمونهٔ موازی گرفته و کمترین مقدار گزارش می‌شود تا یک بستهٔ کند به‌تنهایی نتیجه را خراب نکند.

## روش تست سرعت

دو فایل تست از همان دامنهٔ خود اپ سرو می‌شوند (`speedtest-assets/download-payload.bin` برای دانلود، `speedtest-assets/upload-target.bin` به‌عنوان هدف آپلود). چون این درخواست‌ها هم‌مبدأ هستند، محدودیت CORS اصلاً درگیر نمی‌شود و پیشرفت زندهٔ واقعی (نه تخمینی) در طول تست نمایش داده می‌شود — با چند اتصال موازی برای دانلود و آپلود.

**نیازمندی میزبانی**: وب‌سرور باید به `POST` روی یک فایل استاتیک با پاسخ ۲۰۰ جواب بدهد (nginx و Apache به‌صورت پیش‌فرض این کار را می‌کنند؛ برخی هاست‌های استاتیک این را رد می‌کنند). اگر این قابلیت در دسترس نباشد، اپ به‌صورت خودکار به یک روش پشتیبان (بدون پیشرفت زنده، فقط یک عدد نهایی تقریبی) برمی‌گردد و پیامی نشان می‌دهد که کدام حالت فعال است.

## پایداری داده

با `localStorage`: تم، زبان، DNSهای اضافه‌شده یا ویرایش‌شده توسط کاربر، علاقه‌مندی‌ها، کشورهای سفارشی، و موارد حذف‌شده بین بازدیدها حفظ می‌شوند.

## محدودیت‌های شناخته‌شده

- پینگ DNS در بیشتر موارد «تقریبی» است، نه یک کوئری DNS واقعی (دلیلش در بخش بالا توضیح داده شد).
- تست سرعت وقتی فایل‌های محلی در دسترس باشند چندنخی و با پیشرفت زنده است؛ در حالت پشتیبان به یک عدد نهایی تقریبی محدود می‌شود.
- تشخیص خودکار کشور کاربر پیاده‌سازی نشده (چون سرویس‌های آی‌پی-به-موقعیت رایگان هم معمولاً CORS را می‌بندند)؛ انتخاب کشور دستی است.
- در صورت نبود اینترنت یا مسدود بودن سرویس‌های پشتیبان، پیام خطای مناسب نمایش داده می‌شود، نه عدد جعلی.
